`PRAXA_MCP_TOOLS` is the complete, authoritative list of MCP tools exposed by the Praxa Integration Gateway. You import this array from `@praxa/mcp-contracts` and register its entries with your MCP host — no manual schema authoring required. Every tool definition includes a `name`, human-readable `description`, `inputSchema` (JSON Schema draft-07 compatible), the gateway `operationId`, HTTP `method` and `path`, a `requiredScope` for OAuth authorization, and an `idempotency` field indicating whether the tool mutates state.

Each tool object in the array has the following shape:

```typescript
type PraxaMcpTool = {
  name: string;           // MCP tool name registered with the host
  description: string;    // Shown to the AI model as tool documentation
  inputSchema: object;    // JSON Schema for the tool's input object
  operationId: string;    // Corresponding gateway operation
  method: "GET" | "POST"; // HTTP method used by the gateway
  path: string;           // Gateway path, e.g. /v8/missions/{runId}
  requiredScope: string;  // OAuth scope the token must include
  idempotency: "required" | "safe-read"; // Mutation behaviour
  pathArgument?: string;  // Input field interpolated into the path
};
```

## Tool List

| Tool Name | HTTP Method | Path | Required Scope | Idempotency |
|---|---|---|---|---|
| `praxa_submit_intent` | POST | `/v8/intents` | `missions:write` | `required` |
| `praxa_create_mission` | POST | `/v8/missions` | `missions:write` | `required` |
| `praxa_get_mission` | GET | `/v8/missions/{runId}` | `missions:read` | `safe-read` |
| `praxa_signal_mission` | POST | `/v8/missions/{runId}/signals` | `missions:write` | `required` |
| `praxa_cancel_mission` | POST | `/v8/missions/{runId}/cancel` | `missions:write` | `required` |
| `praxa_search_capabilities` | POST | `/v8/capabilities/search` | `capabilities:read` | `safe-read` |
| `praxa_query_memory` | POST | `/v8/memory/query` | `memory:read` | `safe-read` |
| `praxa_get_skill` | GET | `/v8/skills/{skillId}` | `skills:read` | `safe-read` |
| `praxa_get_trace` | GET | `/v8/traces/{traceId}` | `traces:read` | `safe-read` |
| `praxa_list_goals` | GET | `/v8/context-twin/goals` | `context:read` | `safe-read` |
| `praxa_list_world_certificates` | GET | `/v8/world-model/certificates` | `world:read` | `safe-read` |
| `praxa_get_coverage` | GET | `/v8/coverage` | `coverage:read` | `safe-read` |

Tools with `idempotency: "required"` mutate gateway state and must receive a unique `idempotencyKey` field in their input on every call. Tools with `idempotency: "safe-read"` are read-only and carry no idempotency requirement.

Brief descriptions of what each tool does:

- **`praxa_submit_intent`** — Records natural-language intent for deterministic compilation. It implies no provider action or outcome.
- **`praxa_create_mission`** — Submits a goal to Praxa policy and broker orchestration. Grants no action authority on its own.
- **`praxa_get_mission`** — Reads an authoritative mission projection for a given run ID.
- **`praxa_signal_mission`** — Records a mission signal for policy-controlled handling; does not directly commit a provider effect.
- **`praxa_cancel_mission`** — Requests durable cancellation of a running mission.
- **`praxa_search_capabilities`** — Searches policy-eligible capability manifests before semantic ranking.
- **`praxa_query_memory`** — Queries purpose-filtered memory for the given compartment and purpose.
- **`praxa_get_skill`** — Reads a versioned governed skill and its evidence state.
- **`praxa_get_trace`** — Reads a redacted causal trace.
- **`praxa_list_goals`** — Lists purpose- and compartment-filtered context goals.
- **`praxa_list_world_certificates`** — Lists signed model capability certificates. Certificates grant zero action authority.
- **`praxa_get_coverage`** — Reads reference coverage evidence. Coverage is not a measure of production readiness.

## Using `PRAXA_MCP_TOOLS`

Import `PRAXA_MCP_TOOLS` to iterate all tool definitions, or use `praxaMcpTool` to retrieve a single tool by name. Both are fully typed in TypeScript.

```typescript
import { PRAXA_MCP_TOOLS, praxaMcpTool } from "@praxa/mcp-contracts";

// Iterate all tools — useful when registering with an MCP host
for (const tool of PRAXA_MCP_TOOLS) {
  console.log(tool.name, tool.requiredScope);
}

// Look up a specific tool
const createTool = praxaMcpTool("praxa_create_mission");
console.log(createTool?.inputSchema);
```

A typical MCP server registration loop looks like this:

```typescript
import { PRAXA_MCP_TOOLS, MCP_SERVER_NAME, MCP_PROTOCOL_VERSION } from "@praxa/mcp-contracts";

const server = createMcpServer({
  name: MCP_SERVER_NAME,
  version: MCP_PROTOCOL_VERSION,
});

for (const tool of PRAXA_MCP_TOOLS) {
  server.registerTool({
    name: tool.name,
    description: tool.description,
    inputSchema: tool.inputSchema,
  });
}
```

## Tool Name Convention

Every tool in `PRAXA_MCP_TOOLS` has a name prefixed with `praxa_`. The package name, TypeScript exports, and wire-protocol identifiers therefore use one product namespace: `PRAXA_MCP_TOOLS`, `PraxaMcpTool`, `praxaMcpTool`, and `praxa_*`.

## JSON-RPC Types

`@praxa/mcp-contracts` also exports TypeScript types for the JSON-RPC 2.0 message layer that MCP uses as its transport:

```typescript
import type { JsonRpcRequest, JsonRpcResponse, JsonRpcId } from "@praxa/mcp-contracts";

function handleMessage(message: JsonRpcRequest): JsonRpcResponse {
  return {
    jsonrpc: "2.0",
    id: message.id ?? null,
    result: { /* ... */ },
  };
}
```

Use these types when building the request/response handling layer of your own MCP server implementation on top of these contracts.

<Note>
Any tool with `idempotency: "required"` — `praxa_submit_intent`, `praxa_create_mission`, `praxa_signal_mission`, and `praxa_cancel_mission` — must receive a unique `idempotencyKey` field in its input on every invocation. Reusing the same key for two logically different calls causes the gateway to return the cached result of the first. Generate a fresh UUID v4 per call.
</Note>
