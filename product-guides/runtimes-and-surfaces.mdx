Choose the Praxa surface that matches connectivity, privacy, input mode, and device support.

<Note>
Voice, on-device, iMessage, widget, and application catalog surfaces are product experiences. They are not interchangeable with Execution Fabric or Integration Gateway credentials.
</Note>

## Provided capabilities

| Capability | Status | Surfaces | Who it helps |
|---|---|---|---|
| **Cloud chat app**<br />Use Praxa's primary streaming agent surface with the cloud tool catalog. | Live | iOS, web | Individual, Business, Team, Organization |
| **Apps, Skills, and Workflows catalog**<br />Discover connected apps, reusable skills, and packaged workflows from one catalog. | Live | iOS, web | Individual, Business, Team |
| **Realtime voice mode**<br />Hold low-latency spoken conversations with the Praxa agent. | Live | iOS | Individual |
| **On-device offline model**<br />Run private offline turns with Apple Foundation Models on supported devices. | Live | iOS | Individual |
| **iMessage agent**<br />Message Praxa from the iMessage extension and receive agent replies in the conversation. | Live | iMessage | Individual |
| **Widgets and Live Activities**<br />View current Praxa information from home-screen widgets and supported Live Activity surfaces. | Live | iOS | Individual |

## Example outcomes

1. **Move from text to voice.** Start a supported voice conversation and verify that the available capabilities match the voice runtime.
2. **Use an offline turn.** On a supported Apple Intelligence device, disconnect from the network and run an on-device request.
3. **Find a packaged workflow.** Open the Apps, Skills, and Workflows catalog and inspect the requirements before starting one.
4. **Check a widget surface.** Add a Praxa widget and confirm its displayed information matches the signed-in account.

## Verify the surface

1. Confirm the capability status and listed surface in the [Capability Atlas](/overview/capabilities).
2. Sign in to the intended Praxa product surface and select the correct personal or organization workspace.
3. Exercise the example with the smallest safe scope and inspect the visible result or approval card.
4. Test one unavailable, denied, or disconnected state so the surface fails honestly.
5. Use a developer tutorial only when this guide links to a supported public developer contract.
