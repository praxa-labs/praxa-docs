> **Status:** Minimal personal-tenant durable execution is live for admitted
> partner-preview tenants. The richer agent-builder surface—agent selection,
> context/tool allowlists, policy overrides, generic approvals, organization
> execution, and mature receipts—is unavailable.

Use `praxa_sk_` from a trusted backend to start work that should survive a
client disconnect. Do not expose the key in browser or mobile client code.

```http
POST /v1/execute
Authorization: Bearer praxa_sk_...
Content-Type: application/json
X-AI-Platform-Version: v1
Idempotency-Key: ticket-4471-summary-v1

{
  "apiVersion": "v1",
  "requestId": "ticket-4471-summary-v1",
  "mode": "task",
  "task": {
    "input": "Summarize the supplied support incident and propose the next safe action."
  },
  "idempotencyKey": "ticket-4471-summary-v1"
}
```

A successful submission returns `202` with a `RunResource` and UUID `run_id`.
Reuse the same idempotency key only for retries of the same normalized request.

```http
GET /v1/runs/2f47a86e-72ce-4f27-8ff0-7dc0c959fd35/events
Authorization: Bearer praxa_sk_...
Accept: text/event-stream
Last-Event-ID: 12
```

The current lifecycle is useful for queueing and observing durable work. It is
not yet a replacement for an embedded custom agent that needs bound connectors,
caller-selected tools, or a generic send/write approval. Existing custom-agent
deployments continue on their separate API.

Automatic signed task webhooks and bearer webhook management are active for
admitted personal tenants. Use webhooks for push delivery and keep run polling
or resumable SSE as complementary recovery paths.

Current usage readback reports evidence-bounded model and settled retail usage;
it does not expose a mature receipt describing every tool, policy decision, or
verification step.
