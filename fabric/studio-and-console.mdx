> **Production host:** The developer console is served at
> [`https://platform.praxa.io`](https://platform.praxa.io). Sign-in is at
> [`/sign-in`](https://platform.praxa.io/sign-in), and every deployment exposes
> a verification receipt at
> [`/api/deploy-version`](https://platform.praxa.io/api/deploy-version) that
> identifies the application and the exact stamped commit. On 2026-08-08 that
> receipt identified `praxa-developer-platform` at stamped commit
> `b05a4c54a37e4bb6106d90fc17abbed658ebd680`. The previously documented
> `/developers` nested paths belong to a superseded surface and no longer exist
> on this host.

The console uses your existing Praxa account. It does not create a second
identity, subscription, or organization authority.

## Read the status labels first

This page separates four proof lanes:

- **Live** means the surface is deployed on the production host and behaves as
  described for signed-in accounts.
- **Activation-gated** means the surface is deployed in the console, but a
  named production gate — an upstream authorization proof, migration canary, or
  reviewed egress path — must close before its full authority is claimed.
- **Preview** means the console shows guidance for a documented contract that
  is not traffic-serving.
- **Unavailable** means there is no customer-callable product boundary, and the
  console says so instead of simulating one.

Passing source tests never moves a surface into the live lane, and a deployed
route never silently upgrades an activation-gated authority.

## Authentication and security model

Sign-in supports email/password and Google OAuth, with email confirmation on
new accounts. Password recovery is enumeration-safe and only proceeds from a
fresh recovery link; completing it revokes every other session. Enrolled
accounts step up to AAL2, and the console requires that step-up before any
credential-sensitive mutation — key creation and rotation, webhook mutation,
organization changes, and billing access.

The browser never receives service credentials. Key material returns through
no-store, same-origin handlers and is shown once; authoritative storage keeps a
hashed secret and display suffix, not recoverable plaintext. The server
resolves the signed-in identity and workspace; the browser cannot submit an
arbitrary tenant.

## Superseded surface

Before the 2026-08 cutover, this host was fronted by the consumer-app developer
portal: email-link/OTP fragment callbacks, a durable legal-acceptance gate, and
nested `/developers` routes. The production canaries recorded for that surface
were real and remain part of the historical evidence, but they describe a
surface that no longer fronts `platform.praxa.io`. Consumer-host developer deep
links now redirect to the console above.
