Praxa gives developers separate, explicit contracts for durable task execution,
governed agent missions, MCP tools, observability, webhooks, and read-only
federation across existing memory systems. Start with the outcome you need;
each surface has its own credential, authority, and release boundary.

## Choose an integration surface

| If you need to… | Start with | Credential and authority |
|---|---|---|
| Submit, observe, or cancel a durable task | [Execution Fabric](/fabric) | Personal workspace API key for `https://api.praxa.io` |
| Create a budgeted mission with signals and resumable events | [TypeScript SDK](/sdk/overview) | Short-lived OAuth token and your deployment-specific Integration Gateway origin |
| Add governed operations to an MCP-compatible agent | [MCP Contracts](/mcp/overview) | The public contracts package; runtime calls still use a Gateway token |
| Operate missions from a terminal or CI job | [CLI](/cli/overview) | The same deployment-specific Gateway origin and OAuth token |
| Query Mem0, LangGraph, Zep, Graphiti, Letta, or OpenAI Agents memory | [Memory Federation](/memory-federation/overview) | Provider clients and credentials owned by your backend |
| Stage portable records for lexical query, export, and erasure | [Hosted memory candidate tutorial](/tutorials/hosted-memory-candidates) | Personal workspace key with `memory:read` or `memory:write`; qualification preview |
| Reproduce published performance evidence | [Benchmarks & Research](/benchmarks/overview) | No production credential for public artifacts |

<Warning>
  Do not move credentials between surfaces. In particular, an Execution Fabric
  API key is not an Integration Gateway OAuth token, and a memory-provider
  credential belongs only in the backend process that creates that provider
  client.
</Warning>

## Run your first durable task

Create a personal workspace key with `execute:write`, then send one stable
idempotency key for the logical task:

```bash
curl --fail-with-body https://api.praxa.io/v1/execute \
  -H "Authorization: Bearer $PRAXA_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: weekly-review-2026-08-13" \
  -d '{
    "apiVersion": "v1",
    "requestId": "weekly-review-2026-08-13",
    "mode": "task",
    "task": { "input": "Summarize this week and propose the next safe action." },
    "idempotencyKey": "weekly-review-2026-08-13"
  }'
```

A `202` response proves that the task was admitted or exactly replayed. Follow
the returned run resource or event stream to verify completion; admission alone
does not prove a downstream effect.

## Run a governed mission

If your organization operates an Integration Gateway deployment, install the
public SDK and use the origin and short-lived OAuth token issued by that
deployment:

```bash
npm install @praxa/sdk@0.3.0
```

```ts
import { PraxaClient } from "@praxa/sdk";

const praxa = new PraxaClient({
  baseUrl: process.env.PRAXA_BASE_URL!,
  accessToken: () => process.env.PRAXA_ACCESS_TOKEN!,
});

const mission = await praxa.createMission(
  {
    goalSpec: { task: "Prepare the weekly review" },
    resourceBudget: {
      maximumSteps: 12,
      maximumToolCalls: 8,
      maximumElapsedMs: 120_000,
      maximumParallelism: 2,
    },
  },
  "weekly-review-2026-08-13",
);

for await (const event of praxa.missionEvents(mission.runId)) {
  console.log(event.id, event.event, event.data);
}
```
